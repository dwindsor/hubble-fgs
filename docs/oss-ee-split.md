This document describes how the code between Tetragon Enterprise (EE) and Tetragon OSS is organized.

## Tracing policies

EE includes additional functionality (e.g., L3 and L7 networking events, and file events)  via additional fields in the TracingPolicy spec.

Both [OSS](https://github.com/cilium/tetragon/blob/05de3b487743d668f2065b26f64c1149558577e6/pkg/k8s/apis/cilium.io/v1alpha1/types.go#L36-L46)
and [EE](https://github.com/isovalent/hubble-fgs/blob/3d9b83184bfa1271bcd12cb3d3920f6755e93443/pkg/k8s/apis/cilium.io/v1alpha1/types.go#L71-L81)
define the same structure for a TracingPolicy:
```
type TracingPolicy struct {
        metav1.TypeMeta   `json:",inline"`
        metav1.ObjectMeta `json:"metadata"`
        // Tracing policy specification.
        Spec TracingPolicySpec `json:"spec"`
}
```

The `Spec`, however, differs. The OSS spec is a subset of the EE spec.


[OSS](https://github.com/cilium/tetragon/blob/05de3b487743d668f2065b26f64c1149558577e6/pkg/k8s/apis/cilium.io/v1alpha1/types.go#L75-L92):
```
type TracingPolicySpec struct {
        // +kubebuilder:validation:Optional
        // A list of kprobe specs.
        KProbes []KProbeSpec `json:"kprobes"`
        // +kubebuilder:validation:Optional
        // A list of tracepoint specs.
        Tracepoints []TracepointSpec `json:"tracepoints"`
        // +kubebuilder:validation:Optional
        // Enable loader events
        Loader bool `json:"loader"`
        // +kubebuilder:validation:Optional
        // A list of uprobe specs.
        UProbes []UProbeSpec `json:"uprobes"`


        // +kubebuilder:validation:Optional
        // PodSelector selects pods that this policy applies to
        PodSelector *slimv1.LabelSelector `json:"podSelector,omitempty"`
}
```

[EE](https://github.com/isovalent/hubble-fgs/blob/master/pkg/k8s/apis/cilium.io/v1alpha1/types.go#L90-L113):
```
type TracingPolicySpec struct {
        // ... same as OSS ..
        
        // +kubebuilder:validation:Optional
        // Parser policy specification.
        Parser ParserPolicySpec `json:"parser"`
        // +kubebuilder:validation:Optional
        // File monitoring policy specification.
        FileMonitoring FileSpec `json:"file"`

        // ... same as OSS ..
}
```

Internally, the additional functionality is implemented via "sensors". Sensor code is located in
`pkg/sensors`. Sensors call
[RegisterPolicyHandlerAtInit](https://github.com/cilium/tetragon/blob/f30a94cc603fa6d01f15e1c426dcce47a1f2e0b3/pkg/sensors/sensors.go#L107)
to handle a part of the TracingPolicy Spec, and
[RegisterEventHandlerAtInit](https://github.com/cilium/tetragon/blob/f30a94cc603fa6d01f15e1c426dcce47a1f2e0b3/pkg/observer/observer.go#L49)
to handle specific types of BPF events as generated by BPF programs.

Specifically, the code for each sensor is located in:

- `Kprobe`: [OSS:pkg/sensors/tracing/generickprobe.go](https://github.com/cilium/tetragon/blob/main/pkg/sensors/tracing/generickprobe.go)
- `Tracepoint`: [OSS:pkg/sensors/tracing/generictracepoint.go](https://github.com/cilium/tetragon/blob/main/pkg/sensors/tracing/generictracepoint.go)
- `Uprobe`: [OSS:pkg/sensors/tracing/genericuprobe.go](https://github.com/cilium/tetragon/blob/main/pkg/sensors/tracing/genericuprobe.go)
- `Loader`: [OSS:pkg/sensors/tracing/loader.go](https://github.com/cilium/tetragon/blob/main/pkg/sensors/tracing/loader.go)
- `Exec`: [OSS:pkg/sensors/exec](https://github.com/cilium/tetragon/tree/main/pkg/sensors/exec) and [EE:pkg/sensors/exec](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/exec)
- `Interface`:  [EE:pkg/sensors/network/network.go](https://github.com/isovalent/hubble-fgs/blob/master/pkg/sensors/network/network.go)
- `IP`: [EE:pkg/sensors/ip](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/ip)
- `TCP`: [EE:pkg/sensors/tcp](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/tcp)
- `UDP`: [EE:pkg/sensors/udp](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/udp)
- `HTTP`: [EE:pkg/sensors/http](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/http)
- `TLS`: [EE:pkg/sensors/sockmap](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/sockmap)
- `FIM`: [EE:pkg/sensors/file](https://github.com/isovalent/hubble-fgs/tree/master/pkg/sensors/file)


## Including OSS as a library in EE

The tetragon OSS code is included as a git submodule in the EE repository. The go code is included
as a go module using a `replace`
[directive](https://github.com/isovalent/hubble-fgs/blob/3d9b83184bfa1271bcd12cb3d3920f6755e93443/go.mod#L208)
that points to the go submodule. There are also replace directives for
[github.com/cilium/tetragon/api](https://github.com/isovalent/hubble-fgs/blob/3d9b83184bfa1271bcd12cb3d3920f6755e93443/go.mod#L211)
and
[github.com/cilium/tetragon/pkg/k8s](https://github.com/isovalent/hubble-fgs/blob/3d9b83184bfa1271bcd12cb3d3920f6755e93443/go.mod#L212)
which point to the EE directories of `./api` and `./pkg/k8s`, respectively. This means that the OSS module is
compiled with the EE versions of the gRPC API (`./api`) and K8s objects (`pkg/k8s`).

The gRPC OSS interface is defined in https://github.com/cilium/tetragon/tree/main/api/v1, while the
EE in https://github.com/isovalent/hubble-fgs/tree/master/api/v1.
